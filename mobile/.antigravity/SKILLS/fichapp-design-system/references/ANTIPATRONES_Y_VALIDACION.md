# Antipatrones y validación visual

## Antipatrones visuales prohibidos por defecto

- Gradientes azules/morados genéricos sin justificación de marca.
- Tarjetas para absolutamente todo.
- Sombras grandes o múltiples niveles de elevación innecesarios.
- Esquinas exageradamente redondeadas.
- Colores arbitrarios fuera de tokens.
- Emojis como sustitutos de iconos de interfaz.
- Mezcla inconsistente de familias de iconos.
- Gráficos decorativos sin valor informativo.
- Botones y controles con estilos diferentes entre módulos.
- Tipografías adicionales no autorizadas.
- Grandes bloques de color que reducen legibilidad.
- Diseños que parecen plantillas genéricas sin relación con el contexto de la tarea.

## Antipatrones UX

- Formularios extensos sin agrupación.
- Acciones importantes escondidas sin motivo.
- Confirmaciones para cada interacción.
- Mensajes técnicos sin explicación.
- Estados de carga sin feedback.
- Tablas ilegibles comprimidas en móvil.
- Errores de sincronización ocultos.
- Estados comunicados solo mediante color.
- Operaciones financieras confirmadas visualmente antes de confirmación real.
- Mostrar información o acciones fuera de los permisos del usuario.

## Checklist antes de finalizar

### Identidad
- [ ] Se respetaron paleta y tokens vigentes.
- [ ] Se utilizó Inter.
- [ ] Se respetó geometría moderada.
- [ ] No se introdujeron estilos decorativos arbitrarios.
- [ ] Iconografía consistente.

### UX
- [ ] La tarea principal se entiende rápidamente.
- [ ] Jerarquía visual clara.
- [ ] Acciones frecuentes fáciles de alcanzar.
- [ ] Formularios agrupados y recuperables.
- [ ] Confirmaciones reservadas para acciones relevantes.
- [ ] Estados y feedback definidos.

### Responsive
- [ ] Teléfono pequeño.
- [ ] Teléfono de tamaño habitual.
- [ ] Tablet o pantalla amplia cuando aplique.
- [ ] No hay desbordamientos ni tablas ilegibles.
- [ ] Teclado y áreas seguras no ocultan acciones.

### Datos, permisos y offline
- [ ] No se muestra información innecesaria.
- [ ] Se respetan permisos.
- [ ] Se diferencian guardado local y sincronización.
- [ ] No se declara éxito sin confirmación.
- [ ] Se manejan errores y conflictos relevantes.

### Evidencia
- [ ] Se ejecutaron comprobaciones/pruebas disponibles.
- [ ] Se inspeccionaron capturas reales cuando el entorno lo permitió.
- [ ] Se documentaron limitaciones y asuntos pendientes.

No afirmar que una comprobación se realizó si no existe evidencia.
